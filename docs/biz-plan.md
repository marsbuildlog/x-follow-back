# Twitter 自动回关插件

## 背景

最近简中 X 圈发起了蓝V互关风潮, 但是 Twitter 目前回关或者关注别人会有一个频率限制, 所以如果你有较多人关注的话, 回关需要过一会儿再手动操作一下。

目标用户往往粉丝量较大, 粉丝中混杂大量垃圾账号, 因此不能盲目回关全部粉丝。

## 目标 / 非目标

### 目标

- 自动回关全部认证粉丝(蓝V), 替代手动操作
- 遵守关注频率限制, 控制账号风险
- 可视化查看回关进度与状态

### 非目标 (本期不做)

- 普通粉丝(无认证)的回关
- 多账号支持
- 取关不回关的人等反向功能
- 历史记录展示
- 自动定时触发(后续可加)

## 决策记录

| # | 决策 | 理由 |
|---|------|------|
| 1 | 只处理认证粉丝 | 用户粉丝量大、垃圾账号多, 全量回关会关注一堆垃圾号; 蓝V是天然的质量过滤 |
| 2 | 每日关注上限 400 个 | 达到上限后当日停止 |
| 3 | 持续 30 分钟无法关注则暂停任务 | 判定为被限流, 先暂停避免风险 |
| 4 | 多账号暂不处理 | 只处理当前登录账号 |
| 5 | 不做历史记录展示 | 失败时展示出错信息即可 |
| 6 | UI: 独立 options 页 + x.com 页面顶部注入状态条 | 状态条展示当前进度、今日关注数 |
| 7 | 关注间隔随机 15~30 秒 | 30 秒之内一个(用户后调快, 原 30~90 秒); 400 个约 1~2 小时跑完 |
| 8 | 暂停后手动恢复; 未手动恢复则每隔 1 小时自动尝试恢复 | 兼顾人工控制与无人值守 |
| 9 | 浏览器范围: Chrome + Edge (均为 MV3) | 不做 Firefox |

## 核心流程

1. 通过 https://x.com/{handle}/verified_followers 页面接口拉取认证关注者
2. 过滤掉已关注的账号, 得到待回关列表
3. 通过关注接口逐个发起关注:
   - 每次关注之间随机间隔 30~90 秒(模拟人工)
   - 失败按类型处理(见下方"失败处理策略")
   - 持续 30 分钟无法成功关注 → 暂停任务; 手动恢复, 若未手动恢复则每隔 1 小时自动尝试恢复
   - 当日累计关注满 400 → 当日停止
4. 任务状态持久化到 chrome.storage.local, 浏览器/插件重启后可恢复

## 失败处理策略

> 目前不明确接口会有哪些失败返回, 先按大类处理, 并把原始错误信息展示在 options 页, 等真实运行收集到样本后再细化分类。

| 类型 | 判定(初步) | 处理 |
|------|-----------|------|
| 限流 | HTTP 429 / rate limit 错误码 | 退避重试; 持续 30 分钟未恢复则暂停任务 |
| 受保护账号 | protected account 相关错误 | 标记为跳过 |
| 已关注 / 账号不存在 | already following / not found | 标记为完成或跳过 |
| 未知错误 | 其他 | 记录并展示原始错误信息, 短间隔重试若干次 |

## UI

### options 页(独立页面)

- 待回关列表: 每人一行, 含状态(待处理 / 成功 / 失败 / 跳过)与出错信息
- 任务状态: 运行中 / 暂停 / 已完成
- 暂停时提供手动"恢复"按钮
- 今日关注数与剩余额度

### x.com 页面注入状态条

- 打开 verified_followers 页面时, 在页面顶部注入基本状态:
  - 当前进度(如 37/210)
  - 今日关注数(如 123/400)

## 技术方案

- 浏览器: Chrome + Edge, 均为 MV3
- 存储: chrome.storage.local
- 任务执行: 绑定在打开的 x.com 标签页内运行(content script / 页面注入脚本), 避免 MV3 service worker 被回收导致任务中断
- 接口: 复用页面登录态(cookie + csrf token)调用 x.com 的 GraphQL 接口

## PoC 结论(已实测验证)

| 风险点 | 结论 |
|--------|------|
| x-client-transaction-id 无法自行构造 | 已解决: 在 x.com 页面上下文内捕获页面自身请求的完整请求头并原样重放; 回关模板持久化到 localStorage, 重放时自动刷新 csrf token, 过期时(403)提示手动点一次「回关」刷新 |
| 认证粉丝分页 | 可翻页拉全: `BlueVerifiedFollowers`(GraphQL), count=100/页有效; 注意列表拉完后接口仍返回 cursor, 以「一页 0 人」作为终止条件 |
| 关注接口 | 实际是 v1.1 REST `POST /i/api/1.1/friendships/create.json`(非 GraphQL), body 为 x-www-form-urlencoded, 仅替换 user_id 即可重放, 返回 200 且真实生效 |
| 已关注状态 | BlueVerifiedFollowers 响应不含顶层 following 字段, 状态在用户对象的 `relationship_perspectives.following` |
| 任务运行环境 | 绑定 x.com 标签页内运行; 插件重载后孤儿脚本自动清理, 新实例自动接管未完成任务 |

实测数据: 277 个认证粉丝, 跳过已关注 135 个, 待回关约 142 个, 重放关注真实生效。
