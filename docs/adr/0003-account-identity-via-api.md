# 账号识别: 以 X 接口为准, 不信任侧栏 DOM

互关标签页的 URL 里没有账号名, 主动关注任务(队列/帖子池)按账号分键, 因此每次写入前都要解析"当前登录账号"。此前实现读侧栏账号切换器里的第一个链接——**多账号登录时那里面可能是别的账号**, 实测(2026-10-10)整场搜索的 98 个候选与 200 个帖子被写进了另一个账号的任务键; 且该解析在不同时刻返回不同结果(有时取到别的账号、有时取不到退回最近活跃), 同一次会话里搜索与启动按钮落到了两个键上。

## Decision

- page-hook 新增 `whoami` 消息: 用任一已捕获请求的认证头调 `GET /i/api/1.1/account/settings.json`, 取真实 `screen_name`, 结果缓存 10 分钟。
- `afHandle()` 解析链: **whoami 接口 → 侧栏 DOM(兜底) → 最近活跃**。识别结果变化时记日志(`识别当前账号: @x(之前按 @y 记录)`)。
- 面板展示缓存(refreshCache)与任务写入走同一条解析链, 不再单独猜。
- **回关侧同理**: 任务账号从页面 URL 读(handle 形如 /:handle/verified_followers), 但 URL handle 必须等于 whoami 结果才采用——逛别人的关注/粉丝列表时不再误认(过去会把拉取到的粉丝写进别人的任务键); 非自己主页时展示退回最近活跃账号。
- **whoami 数据源迭代(2026-10-10 晚)**: settings.json 实测会整体 429(code 88), verify_credentials 已下线(404)——接口兑底不可靠。改为**被动喍探页面自己的 Viewer 响应**(零额外请求, 与页面认定的登录账号同源), settings.json 降为兑底并加 5 分钟失败负缓存。
- **身份不明时不采信 URL handle**: 宁可返回空串退回最近活跃账号, 也不再盲信 URL——盲信曾把行为静默退化为旧 bug。autoTick 的接管/恢复锚定最近活跃账号(任意页面可继续); 回关定时补拉改由控制台宿主按 autoFetchMin 触发(ADR-0010)。

## Consequences

- 每个标签页 10 分钟一次 settings.json 请求, 可忽略的额度代价。
- 若多账号切换, 任务键跟着真实会话走; 历史上写错账号的数据需手工迁移(控制台对 chrome.storage 做键间合并)。
- whoami 不可用时(极端: 无任何捕获头)退回旧行为, 兼容性不降。
