# 回关与主动关注: 两队列一循环, 回关逐条优先

账号级的关注资源(X 的 24h 关注上限与限流)决定了同一登录账号下的回关与主动关注不能各跑各的循环: 两个并行循环会互相抢额度, 限流退避也会互相干扰。因此决定: **两个任务各自独立队列(数据独立、独立启停), 但共享同一个关注循环与账号级每日计数**; 循环每次取下一个人时**先查回关队列、空了才取主动关注队列**(逐条优先)。

## Considered Options

- **合并成一个队列**: 一次关注同时满足两边, 但回关条目会与候选人条目混排, 无法独立启停与统计, 来源语义丢失。拒绝。
- **两个循环并行**: 天然隔离, 但额度竞争让"回关优先"无法保证, 且 429/161 的退避状态要双份维护。拒绝。
- **清空切换**(先跑完回关队列再跑主动关注): 曾被考虑, 但会让主动关注批次期间新到的粉丝等待数十分钟, 损害"及时回关"的信用信号。拒绝。
- **逐条优先**(采纳): 实现最简单(取队头前多查一个队列), 回关时效最好。

## Consequences

- 主动关注不设独立的每日子限额——回关优先本身就是额度保护(2016-10 定稿时评估过子限额, 决定不加)。
- 两种任务的暂停/退避状态(429、错误码 161、连续失败)是循环级而非任务级, 任一任务触发即对整个循环生效。
